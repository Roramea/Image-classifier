# 图片分类器 - 模块耦合关系与依赖关联文档

## 一、项目概述

本项目是一个基于 PyQt5 的图片分类工具，采用 **MVP (Model-View-Presenter)** 架构模式，将界面展示、业务逻辑和数据管理分离，实现了图片扫描、相似度分析、重复检测、分类管理等功能。

### 项目目录结构

```
文件分类器/
├── app.py                    # 应用入口
├── classifier_configs/       # 配置文件存储目录
├── core/                     # 核心工具层（无业务逻辑依赖）
│   ├── classification_manager.py  # 分类配置管理
│   ├── debug_manager.py           # 调试日志管理（单例）
│   ├── image_scanner.py           # 图片扫描工具
│   ├── observer.py                # 观察者模式基类
│   ├── scan_thread.py             # 扫描线程
│   ├── simple_hash.py             # 图像哈希算法
│   └── utils.py                   # 通用工具函数
├── dialogs/                  # 对话框组件（纯 View）
│   ├── duplicate_detail_dialog.py
│   ├── folder_select_dialog.py
│   ├── hash_analysis_dialog.py
│   ├── settings_dialog.py
│   ├── shortcut_input_dialog.py
│   └── storage_clean_dialog.py
├── presenters/               # 演示者层（业务协调）
│   └── main_presenter.py
├── services/                 # 服务层（业务逻辑）
│   ├── classification_service.py
│   ├── duplicate_service.py
│   ├── hash_analysis_service.py
│   └── image_cache_service.py
├── views/                    # 视图层
│   └── main_window.py
└── widgets/                  # 自定义控件
    └── scrolling_label.py
```

## 四、耦合类型分类

### 4.1 耦合类型定义

| 耦合类型 | 描述 | 示例 |
|---------|------|------|
| **直接导入耦合** | 通过 `import` 语句直接引用其他模块 | `from core.debug_manager import debug_manager` |
| **构造注入耦合** | 通过构造函数参数注入依赖对象引用 | `ClassificationService.__init__(self, classifier)` |
| **Qt 信号/槽耦合** | 通过 PyQt5 的信号机制进行跨对象通信 | `self.scan_thread.progress.connect(...)` |
| **Observer 模式耦合** | 通过观察者模式订阅/发布事件 | `hash_service.on('progress_updated', callback)` |
| **单例访问耦合** | 全局共享的单例对象，所有模块都可访问 | `debug_manager.log_info(...)` |

## 五、层间依赖规则

### 5.1 标准依赖流向（推荐）

```
View (views/, dialogs/)
    ↓ 调用 Presenter 方法
Presenter (presenters/)
    ↓ 创建/调用 Service
Service (services/)
    ↓ 调用 Core 工具 / 持有 Manager
Core (core/)
    ↓ 无外部业务依赖
```

### 5.2 实际依赖关系分析

#### ✅ 符合分层规则的依赖

| 依赖关系 | 描述 |
|---------|------|
| `MainWindow → MainPresenter` | View 通过构造注入持有 Presenter |
| `MainPresenter → ClassificationService` | Presenter 创建并调用 Service |
| `ClassificationService → ClassificationManager` | Service 通过构造注入持有 Manager |
| `MainPresenter → ScanThread` | Presenter 创建后台线程 |
| `ScanThread → ImageScanner` | 线程使用扫描工具 |

#### ⚠️ 跨层依赖（需关注）

| 依赖关系 | 描述 | 风险等级 |
|---------|------|---------|
| `MainWindow → dialogs/*` | View 直接创建对话框（合理，同属 View 层） | **低** |
| `MainWindow → core.utils` | View 直接使用工具函数（合理，工具无业务逻辑） | **低** |
| `MainPresenter → ClassificationManager` | Presenter 直接使用 Manager（合理，Manager 是配置中心） | **低** |
| `HashAnalysisDialog → HashAnalysisService` | 对话框直接持有 Service 并订阅事件（特殊设计） | **中** |

#### 🔄 双向依赖（需要注意）

| 依赖关系 | 描述 | 风险等级 |
|---------|------|---------|
| `MainWindow ↔ MainPresenter` | Window 创建 Presenter 并传入 `self`，Presenter 持有 `self.view` | **中** |
| `HashAnalysisDialog ↔ HashAnalysisService` | Dialog 订阅 Service 事件，同时通过信号链触发 Service 操作 | **中** |

## 六、跨模块数据流

### 6.1 图片扫描流程

```
用户点击"选择文件夹"
    ↓ MainWindow.select_folder()
MainPresenter.select_folder()
    ↓ 调用 View
MainWindow.show_folder_dialog()
    ↓ 用户选择路径
MainPresenter.on_folder_selected(folder_path)
    ↓ 创建线程
ScanThread(folder_path)
    ↓ 后台扫描
ImageScanner.scan_folder()
    ↓ 信号通知完成
MainPresenter.on_scan_finished(image_paths)
    ↓ 更新服务状态
ClassificationService.set_groups()
    ↓ 更新 UI
MainWindow.show_current_image()
```

### 6.2 哈希分析流程

```
扫描完成后自动触发
    ↓
MainPresenter._start_hash_analysis(image_paths)
    ↓ 创建 Service 和 Dialog
HashAnalysisService(threshold) + HashAnalysisDialog
    ↓ Dialog 订阅 Service 事件
hash_service.on('progress_updated', callback)
    ↓ Dialog 启动分析
hash_service.start_analysis(image_paths)
    ↓ Service 后台执行（3个阶段）
ImageScanner.compute_md5() → compute_image_hash() → group_by_similarity()
    ↓ 事件通知
analysis_finished_signal → MainPresenter.on_hash_finished()
    ↓ 更新状态
ClassificationService.apply_similar_groups()
DuplicateService.set_duplicates()
    ↓ 更新 UI
MainWindow.show_current_image()
MainWindow.update_duplicate_list()
```

### 6.3 分类操作流程

```
用户按快捷键或点击按钮
    ↓
MainWindow.keyPressEvent()
    ↓
MainPresenter.handle_key_press(key_str)
    ↓
MainPresenter.classify_image(category)
    ↓
ClassificationManager.classify_image(image_path, category)
    ↓ 文件移动
shutil.move(image_path, target_path)
    ↓ 更新状态
ClassificationService.mark_processed()
ClassificationService.add_classify_history()
    ↓ 更新 UI
MainWindow.on_image_classified()
MainWindow.show_current_image()
```

## 七、关键设计模式

### 7.1 MVP 模式

- **View**: `MainWindow` + 各 `Dialog`，负责 UI 展示和用户交互
- **Presenter**: `MainPresenter`，负责协调 View 和 Service，处理业务流程
- **Model**: `services/` + `core/classification_manager.py`，负责数据管理和业务逻辑

### 7.2 观察者模式

- `Observer` 基类定义了 `on()` 和 `emit()` 方法
- `HashAnalysisService` 继承 `Observer`，发布分析进度事件
- `HashAnalysisDialog` 订阅这些事件，实现跨线程 UI 更新

### 7.3 单例模式

- `DebugManager` 通过 `__new__` 实现单例，全局共享日志实例
- 所有模块导入 `debug_manager` 即可使用

### 7.4 工厂模式（隐式）

- `MainPresenter._init_services()` 创建所有 Service 实例
- 集中管理依赖创建，便于测试和替换

## 八、依赖风险与优化建议

### 8.1 潜在风险

| 风险点 | 描述 | 影响 |
|-------|------|------|
| **MainWindow ↔ MainPresenter 双向依赖** | Window 和 Presenter 互相持有引用 | 增加测试难度，可能导致循环引用 |
| **HashAnalysisDialog 直接持有 Service** | Dialog 需要知道 Service 的接口细节 | 降低 Dialog 的可复用性 |
| **debug_manager 全局依赖** | 所有模块都依赖单例 | 难以进行单元测试隔离 |
| **ClassificationManager 职责过重** | 同时负责配置、缓存、记忆管理 | 违反单一职责原则 |

### 8.2 优化建议

1. **引入依赖注入框架**：使用 injector 或简单的依赖容器，减少手动构造注入代码

2. **拆分 ClassificationManager**：
   - `ConfigManager`: 处理快捷键配置和设置
   - `CacheManager`: 处理哈希缓存
   - `MemoryManager`: 处理重复图片记忆

3. **引入接口抽象**：为 Service 层定义抽象接口，便于测试和替换实现

4. **使用依赖注入替代单例**：将 `debug_manager` 通过构造函数注入，便于测试时替换

## 九、总结

### 9.1 架构特点

- **分层清晰**：View → Presenter → Service → Core 的单向依赖链基本成立
- **职责分离**：各层职责明确，View 不处理业务逻辑，Service 不操作 UI
- **异步处理**：扫描和哈希分析使用后台线程，保持主界面响应
- **事件驱动**：通过 Qt 信号和 Observer 模式实现松耦合通信

### 9.2 改进空间

- 部分模块存在双向依赖，可通过接口抽象进一步解耦
- `ClassificationManager` 职责过重，建议拆分
- 全局单例 `debug_manager` 影响可测试性，建议改为依赖注入
